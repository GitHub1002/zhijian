# API 接口与代码规范

## 接口约定

- JSON 字段使用 snake_case，错误响应统一返回 `detail`。
- 认证失败返回 401，权限不足返回 403，资源不存在返回 404。
- 参数不合法返回 422，并在 `detail` 中说明哪个字段不符合要求。
- 写操作应具备幂等性或提供明确的冲突提示。重复提交同一张已存在的申请时，返回已有结果，不创建第二份。
- 列表接口必须分页。未传页码时默认第 1 页、每页 20 条，单页不超过 100 条。

## 权限

涉及权限的路径必须在服务端再次校验，不能只依赖前端隐藏按钮。用户未获批某个知识库时，检索、下载和问答都不得返回该库内容。用问答套取未授权正文的，与直接下载一样返回拒绝。

认证失败与权限不足要分开：没有登录是 401，登录了但库未获批是 403。不要把两种情况都写成“没有权限”。

## Python 规范

- 函数保持单一职责。一个函数里既查权限又写索引又拼提示词时，拆开。
- 外部输入必须校验类型、长度和允许的枚举值，不把原始字符串拼进查询。
- 数据库查询使用参数绑定。
- 异常要让调用方知道失败原因。捕获后返回空列表冒充“没有数据”的写法不允许出现在权限和检索路径上。
- 密钥只从环境变量读取，不写进代码、文档和日志。

## 提交前检查

运行语法检查、单元测试和最小化接口回归，确认迁移脚本在已有数据库上可重复执行。回归至少覆盖：未登录访问、已登录但无库权限、有权限的检索、重复提交写操作。

## 常见问题

**问：前端已经按权限藏了按钮，后端还可以暂时不校验吗？**
不可以。隐藏按钮只影响界面，接口必须单独拒绝。

**问：字段能不能用驼峰？**
对外 JSON 不用驼峰。内部变量可以，序列化时转换成 snake_case。
