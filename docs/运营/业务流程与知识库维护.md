# 业务流程与知识库维护

## 文档入库

业务负责人每月检查一次制度和 FAQ。发生流程变更时，应在生效日前更新文档，并在标题或正文中标注生效日期。

- 文档放入 `docs/` 下对应目录：人事用 `hr`，设备与安全用 `it`，发布与故障用 `运维`，客服与业务流程用 `运营`，接口与工程规范用 `开发`，问答与提示词用 `人工智能`。
- 更新 Markdown 后必须重建索引。只改文件、不重建索引的，智检仍会回答旧内容。
- 同一规则只保留一份正文。其他文档需要引用时写文档名，不把数字再抄一遍，避免后来只改了一处。

## 质量检查

检查内容是否有负责人、适用范围、版本时间和例外条件；删除已经失效的临时通知，避免同一问题存在互相矛盾的答案。

每月检查至少确认这四项：

1. 金额、时限、天数是否和现行审批单一致。
2. 是否还有“尽快”“及时”“适当”这类无法检索的词。能写数字的写成数字。
3. 失效公告是否已删除或标明失效日期。
4. 标题是否能单独表达主题。只写“说明”“补充”的文档要改名。

## 生效与作废

- 新制度在正文首段写明生效日期。生效日期之前的提问，仍按旧文档回答；索引中不应同时保留两份互相矛盾且都未标明日期的正文。
- 作废文档从 `docs/` 删除后重建索引。不要把作废内容留在文件末尾“备查”，检索会把旧规则一起送进回答。

## 常见问题

**问：临时通知只生效三天，要不要写进知识库？**
要写，并且首段写明起止日期。到期当天删除并重建索引。只发在群里、不入库的通知，客服和问答都无法引用。

**问：谁可以改制度正文？**
业务负责人改自己职责内的文档。HR 制度由人力资源部改，发货口径由客服负责人改。其他人发现错误时提交修改建议，不直接覆盖。
