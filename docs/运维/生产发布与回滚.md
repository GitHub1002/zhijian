# 生产发布与回滚

## 发布前检查

1. 确认变更单、负责人和回滚版本已经登记。没有回滚版本的变更不进入发布窗口。
2. 在预发布环境完成冒烟测试，重点验证登录、检索、上传和权限接口。
3. 检查数据库备份、磁盘空间、服务健康状态与错误日志。核心数据备份须在发布前 24 小时内成功，备份规范见《数据备份规范示例》。
4. 发布窗口开始前通知相关业务负责人。常规窗口为工作日 10:00–16:00，周五 16:00 后不开始新的常规发布。

## 发布步骤

- 先发布后端，再发布前端静态资源。前端先发布会导致页面调用尚未存在的接口。
- 使用健康检查接口确认服务可用。
- 观察 5 分钟错误率、响应时间和检索命中情况。
- 无异常后通知业务方完成发布。

智检发布时额外确认：已授权用户只能检索到获批库，未获批库的提问被拒答且不扣每日额度；索引重建在低峰执行，重建期间不删除正在使用的向量目录。

## 回滚标准

出现持续 5 分钟以上的 5xx、数据越权、关键流程不可用或错误率显著升高时，应立即回滚。回滚后保留日志和变更记录，并由运维负责人复盘。

错误率显著升高指与发布前 30 分钟相比，5xx 比例上升超过 2 个百分点，或登录、检索任一核心接口成功率低于 99%。只影响单个非核心页面且有临时提示的，可以先观察，不立即回滚。

## 回滚步骤

1. 值班人在处理群声明开始回滚，暂停继续发布。
2. 先回滚后端到变更单登记的版本，再回滚前端静态资源。
3. 再次执行登录、检索、上传、权限四项冒烟。
4. 数据库变更若已执行且不可逆，不通过“再发一版”掩盖，按变更单中的数据修复方案处理，并升级为 P0 或 P1。

## 常见问题

**问：预发布通过、生产发布后只有一位用户报错，要回滚吗？**
先确认是否为权限或缓存问题。不能在 5 分钟内排除越权或 5xx 的，按回滚标准执行。

**问：紧急修复能否跳过预发布？**
P0 止血可以先回滚或关闭入口。新的修复版本仍须有变更单；无法走预发布时，由值班负责人和部门经理同时同意，并在恢复后补测试记录。
