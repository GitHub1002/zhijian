# Knowledge Document Search

## 目标

只从知识库检索到的文档片段回答问题，不把模型常识当作企业事实。回答保持简洁，并在关键结论后保留来源引用。

## 检索流程

1. 接收已登录用户的问题，并先检查用户当天的 10 次咨询额度。
2. 使用向量检索从 `knowledge_docs` 集合获取相关片段；没有命中时明确告知用户。
3. 将同一组对话的最近问题作为上下文，但永远以文档片段为事实来源。
4. 生成不超过 480 字的要点式回答，先给结论，再列必要步骤，并返回 `answer_id`、`trace_id` 和可点击的来源信息。
5. 每次回答后允许用户点赞或点踩；点踩时选择原因，可标记具体来源问题。

## 反馈与轨迹

- 每次回答（包括拒答）写入 `answer_traces` 与 `retrieval_candidates`，记录查询改写、各路分数、排名和耗时。
- 用户反馈写入 `feedback`，包含情感、原因分类、评论、来源标记和关联的 `trace_id`。
- 反馈只做规则分流，不调用大模型；管理员在反馈队列中复核并决定修检索、修生成还是修文档。
- 个人长期策略 `assistant_memory` 已下线；旧数据可用 `scripts/archive_memory.py` 导出后归档。
- 高赞回答保留在反馈队列中，供后续人工筛选和 few-shot 评估。

## 质量规则

- 点踩必须至少选择一个原因；选择“其他”时评论不少于 10 个字符。
- 点赞允许不填写评论，但仍记录情感和来源。
- 用户隔离：只读取当前登录用户的回答、反馈和轨迹。
- 额度和权限由后端校验，前端展示只是提示，不能作为安全边界。
- 任何检索或提示词改动都必须先用 golden set 回归，再进入小流量实验。
